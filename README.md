# Agent Library — professional skills and specialist agents

A modular, tested library of **45 Agent Skills** and **14 Claude Code subagents** that turn recognised
engineering, software, product, finance and AI-governance frameworks into practical procedures backed
by **deterministic, stdlib-only Python tools**, schemas, templates and pass/fail fixtures.

It is a professional *aid*, not an authority. It does not certify, approve or make compliance, safety,
credit or deployment decisions; every such decision is routed to a named human.

```
python3 scripts/run_all_checks.py      # structure · catalogue sync · unit + fixture tests · demo reproduction
```

## Use it on a project (3 steps)
1. **Select** — describe the project in a profile and get a justified selection with exclusions,
   oversight level, required human sign-offs and a phased workflow:
   `python3 .claude/skills/select-frameworks/scripts/select_frameworks.py profile.json --markdown`
2. **Install** — dry-run first; conflicts are refused, nothing is overwritten silently:
   `python3 scripts/install_packs.py --target ../my-project --packs systems-engineering` then `--apply`.
3. **Work** — open the project in Claude Code; skills and agents are discovered from `.claude/`. Agents
   run the skills' scripts and report exact commands and exit codes.

Details, other tools and updating: [`docs/INSTALL.md`](docs/INSTALL.md).

## How quality is controlled
| Gate | Command | What a PASS means — and does not mean |
|---|---|---|
| Structure | `scripts/validate_library.py` | Skills meet the open Agent Skills spec (spec-only keys, names, sections, references, stdlib-only scripts); agents have explicit tool allowlists, reviewers are read-only, referenced skills exist; packs, registry, NASA 17-process map and crosswalks are consistent. **Not** content correctness. |
| Catalogue sync | `scripts/build_catalog.py --check` | Router catalogue and capability guide match the skills/agents. |
| Unit + fixture tests | `python3 -m unittest discover -s tests -t .` | Known-answer calculations reproduce; every checker passes its *pass* fixture and detects the seeded defects in its *fail* fixture; validator mutation tests catch broken libraries. **Not** professional validation. |
| Assurance language | `independent-review/scripts/claim_check.py` | No unbacked "approved/compliant/safe/certified" or invented research claims in demo outputs. A language screen only. |
| Demo reproduction | `examples/run_demos.py --check` | Demo outputs regenerate identically from inputs. |
| Source freshness | `scripts/source_freshness.py` | Which sources are due for re-checking; reachability is not proof of unchanged content. |

## Source integrity — read this
The build environment's network policy blocked most publisher sites. Sources whose official material
is on GitHub were read at primary level (**VERIFIED**: Google eng-practices, OWASP ASVS 5.0.0, GOV.UK
Design System, DORA; **PARTIALLY_VERIFIED**: NIST SSDF via NIST's OSCAL catalogue). The other 14 are
**INACCESSIBLE**: their skills implement well-established methods from public knowledge with secondary
corroboration, and every section number, rate or clause taken from them is marked *(unverified)*.
Ledger: [`sources/registry.json`](sources/registry.json), per-source audits in
[`sources/audits/`](sources/audits/), mappings in [`docs/crosswalks/`](docs/crosswalks/).
Re-verify these before relying on them for regulated or safety-relevant work.

## Key rules (enforced or tested)
- Numeric design values are *proposed* until an owner approves them; plans are not results.
- No agent reviews or approves its own work; reviewer agents cannot write files.
- Only named humans approve gates, baselines, risk acceptance, physical tests, regulatory
  conclusions, credit decisions and deployments.
- External content is untrusted data; no secrets, no real personal data, synthetic examples only.
