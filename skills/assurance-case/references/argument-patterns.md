# Argument patterns (library guidance)

Each pattern says how a claim is split and what makes the split sufficient. State the sufficiency
condition in the claim's `argument` field.

| Pattern | Split the claim by | Sufficient when | Typical evidence |
|---|---|---|---|
| Requirement coverage | each in-scope requirement or chapter (e.g. ASVS chapters, SWE ids for the class) | the in-scope set is complete (generated by a tool, e.g. `asvs checklist`, `nasa-swe matrix`) | verification report rows, test results |
| Process + product | "built by an adequate process" and "the product has the property" | both hold; process alone is never enough | SSDF assessment; ASVS verification |
| Hazard / risk mitigation | each identified hazard or risk | the hazard/risk list is complete and each is mitigated or accepted by an authority | hazard analysis, risk register, acceptance records |
| Life-cycle phase | design, implementation, verification, operation | each phase's claim holds for this version | review records, test reports, monitoring plan |
| Independent confirmation | the developer's claim and an independent check | independence is real (organisation, budget, technical) | IV&V or audit report |
| Residual risk acceptance | each residual risk | the accountable authority accepted it in writing | signed acceptance (E2+), conditions |

## Anti-patterns

- **Evidence by volume:** many weak (E1) items do not add up to one strong one.
- **Tool output as proof:** a scan with no findings shows absence of *detected* issues only.
- **Hidden gaps:** omitting a subclaim because it lacks evidence; mark it `undeveloped` instead.
- **Circular support:** a claim supported by a subclaim that restates it (the checker catches structural cycles,
  not paraphrased ones).
