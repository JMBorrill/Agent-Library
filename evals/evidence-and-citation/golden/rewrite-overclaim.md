Our build pipeline has controls that support the NIST SSDF practice of reviewing code for vulnerabilities
[nist-ssdf PW.7.1, p. 23]. Repository settings and the pull-request history indicate that changes receive
peer code review before merge; this is documented but not independently verified (claim strength E2).

Code review reduces, but cannot eliminate, the likelihood that vulnerabilities reach production.

Evidence needed to strengthen the statement: branch-protection configuration export, a sample of merged pull
requests showing approving reviews, and the review checklist used. Whether the pipeline conforms to the SSDF is
a judgement for the accountable authority (the organisation's security assurance lead), not this report.
