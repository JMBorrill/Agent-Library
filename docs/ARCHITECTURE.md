# Architecture

The library has four layers. Each layer is usable on its own; together they give Claude (or a person) a
repeatable, checkable way to apply professional frameworks.

```
            ┌──────────────────────────────────────────────────────────────┐
  Orchestr. │ commands/*.md  →  workflows/*.yaml  →  review-board-chair     │  stage gates, decision record
            └──────────────────────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────────────────────┐
  Agents    │ agents/*.md  specialist subagents (systems-engineer,          │  role + procedure + tools
            │ application-security-verifier, ai-risk-assessor, ...)        │
            └──────────────────────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────────────────────┐
  Skills    │ skills/<name>/SKILL.md + references/ + templates/             │  method knowledge (progressive
            │                                                              │  disclosure), artefact templates
            └──────────────────────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────────────────────┐
  Tools &   │ catalog/*.json  ←  scripts/extract/*.py  ←  sources/pdfs/*    │  deterministic, cited data
  data      │ agentlib/frameworks/*.py  (python -m agentlib <framework> …)  │  calculators, checklists, validators
            └──────────────────────────────────────────────────────────────┘
  Quality:  agentlib validate (structure) · pytest (tools) · agentlib eval (skills) · evidence check (outputs)
```

## Design principles

1. **Ground truth comes from pinned sources.** Catalogs are generated by scripts from the SHA-256-pinned
   PDFs and every item carries a PDF page. Skills cite edition and pages. Nothing is cited from memory.
2. **Models reason; tools calculate and check.** Discounting, compliance-matrix generation, checklist
   scoping, requirement linting and identifier validation are deterministic Python, so results are
   reproducible and testable. Skills instruct Claude to call the tools rather than compute in-context.
3. **Progressive disclosure.** `SKILL.md` stays short and procedural; detail sits in `references/` and is
   loaded on demand, following Anthropic's Agent Skills guidance.
4. **Honest claims.** The evidence checker and the claim-strength scale prevent over-claiming;
   every skill ends with limitations; decisions are attributed to an accountable human authority.
5. **Everything is validated.** Front matter, sections, links, catalogs (page ranges), workflow wiring
   (agents/skills/artefacts), eval suites (goldens must pass, negatives must fail) and the generated
   registry all run in CI.

## Data flow for a typical review

1. `/secure-delivery-review` (command) → `review-board-chair` runs `python -m agentlib workflow init secure-software-delivery`,
   which scaffolds a review folder (`PLAN.md`, `state.json`, artefact stubs) from `workflows/secure-software-delivery.yaml`.
2. Stage `scope` → `application-security-verifier` loads `skills/owasp-asvs/`, runs
   `python -m agentlib asvs checklist --level 2` (catalog `owasp-asvs-5`), writes a verification plan.
3. Gates are recorded with `agentlib workflow gate` (refused while artefacts are stubs or earlier gates are open); gates run validators (`asvs check-assessment`, `ssdf check-assessment`), `evidence-auditor` runs
   `evidence check`, and the chair writes `templates/review-board-decision.md`.

## Extension points

- New framework: add a catalog + extraction script, a module in `agentlib/frameworks/` with
  `register(subparsers)`, a skill, an agent and an eval suite (see `docs/AUTHORING.md`).
- New workflow: add `workflows/<id>.yaml`; the validator checks its wiring. Add a command to launch it.
- New grader: add a `grade_*` function to a framework module and reference it from an eval suite.
