# Framework selection and project integration

## Purpose
Apply the smallest sufficient set of professional frameworks to a project, explain why each was chosen
or rejected, and expose where human authority is needed — instead of activating every skill.

## When to use
- Starting a project with this library; onboarding the library into an existing repository.
- Scope change: hardware, AI, lending/regulated finance, personal data, multi-tenancy or space context
  is added or removed.

**Do not use when:** you already know the single skill you need for a narrow task — just use it.

## Inputs
Required: project profile JSON (`assets/templates/project-profile.json`): name, description,
objectives, stage, risk_class, jurisdiction, flags (hardware, software, ai, finance, lending,
personal_data, multi_tenant, ui, external_users, safety_critical, regulated,
decisions_about_individuals, …). Explicit flags beat keyword inference — set them deliberately.
Data: `assets/data/catalog.json` (generated by `scripts/build_catalog.py` in the library repository),
`assets/data/routing-rules.json` (library heuristics).

## Procedure
1. **Interview the owner** (or read the brief) and fill the profile; state unknowns rather than guessing
   flags. Ask specifically: physical hardware or tests? AI/ML? decisions about individuals? money/credit?
   personal data? multi-tenant SaaS? jurisdiction? regulated activity? stage?
2. **Run**: `python3 scripts/select_frameworks.py profile.json --markdown > framework-selection.md`
3. **Review the proposal with the owner**: confirm selected packs and the reasons; challenge exclusions
   (a wrong exclusion is more dangerous than an extra skill); note sources marked not VERIFIED.
4. **Tailor rigour** within selected packs (`se-technical-planning` for engineering projects).
5. **Install** into the project — dry-run first, never overwriting existing configuration:
   `python3 scripts/install_packs.py --target <dir> --skills ... --agents ...` (from the library root),
   inspect the plan, then add `--apply`.
6. **Record** the selection, owner approval and date in the project (`framework-selection.md`); revisit
   on scope change.

## Decision criteria
| Signal | Effect |
|---|---|
| Hardware, physical tests, safety-critical or high risk | systems-engineering pack |
| Space/small-body keywords | space-engineering (requires systems-engineering) |
| Software built | software pack; deployed service/personal data/multi-tenant → reliability-security |
| External users/customers | product; UI → ux |
| Revenue model, investment, lending | finance-credit; UK + regulated → `finance-fca-scope-check` |
| AI/ML component | ai-governance; decisions about individuals/agentic tools → `ai-human-oversight` |
| Safety-critical, regulated, high risk, or AI deciding about people | oversight **high** |
| Always | `independent-review` |

## Outputs
`framework-selection.md` (or `--json`), the install plan, and the owner's recorded approval.

## Validation
Exit 0 ⇒ profile valid and a selection produced. Tests (`tests/test_select_frameworks.py`) pin the
selections for the three reference projects and check every proposed skill/agent exists. The routing
is a heuristic proposal — it does not determine legal or regulatory applicability.

## Examples
- `assets/examples/profile-aster.json` → systems-engineering, space-engineering (incl. low-gravity
  mobility), software, orchestration; finance-credit, product excluded; oversight high.
- `assets/examples/profile-mortgage.json` → finance-credit incl. FCA triage and criteria modelling,
  ai-governance incl. human oversight, reliability-security, product, ux, and core systems-engineering
  skills (high risk: requirements, V&V, risk, gates); space excluded; oversight high.
- `assets/examples/profile-aiops.json` → product, ux, software, reliability-security, ai-governance,
  finance-credit (unit economics); systems-engineering and space excluded.
- `assets/examples/profile-fail.json` → exit 1 (`no-description`, `risk-class`).

## Escalation and stop conditions
- Regulated, safety-critical or AI-decisions-about-individuals projects: the proposal must be reviewed
  by the corresponding human authority before work proceeds.
- If the owner cannot answer key profile questions, record them as open and select conservatively.

## References
- Packs map to registered sources; access status per source is printed in the output (see
  `sources/registry.json` and `sources/audits/`). Routing rules are original to this library.
